# 生产与商业化就绪基线

## 当前结论

当前系统具备可运行的 dev 全栈基线，包括实时模型、PostgreSQL 同步、OIDC、会话、限流、备份和自动部署，但尚不满足公开生产发布条件。dev 自动部署依赖个人开发机连接内网服务器，只用于持续验收，不能视为生产交付架构。

## 上线门槛

### 身份与数据安全

- 使用托管身份提供商替换 Dex 静态测试账号，完成注册、找回、MFA 与异常登录策略。
- 对所有用户数据验证服务端租户隔离，并增加越权与批量访问测试。
- 使用云端密钥管理和短期身份，不在主机文件、CI 变量或日志中保存长期模型与部署凭据。
- 完成隐私政策、服务条款、数据处理方清单、用户同意、数据导出与删除时限。

### 可靠性与运维

- 建立独立 CI/CD Runner、受保护生产环境、不可变制品、审批、健康检查与一键回滚。
- 当前 GitHub CI 只授予仓库内容读取权限，第三方 Actions 固定到不可变提交，checkout 不保留短期凭据，任务具有有界总时限；Dependabot 每周检查 npm 与 Actions 更新。每次 CI 都会审计完整锁文件中的高危和严重漏洞；拉取请求工作流还配置了只读依赖变更审查，阻止所有范围的中危及以上漏洞，并且只允许项目当前审核过的 SPDX 许可证集合。但仓库级 Dependency Graph 当前未启用，GitHub 因此拒绝运行该审查；在仓库 Advanced Security 设置中启用并通过 PR #7 验证前，不能把这项 PR 门禁视为生效。包契约、`.nvmrc`、CI 与 dev 部署统一限定在 Node 22，当前本地验证版本、dev 用户服务和部署脚本固定为 22.23.1，包契约的最低版本为 22.22.2；这使 jsdom 30 可以在本地、CI 与 dev 一致验证，临时的主版本忽略已移除。`package.json` 用显式兼容范围替代浮动 `latest` 并限制受支持的 Node 主版本，避免全新安装静默跨越运行时或依赖主版本。当前许可集合与 GitHub 依赖图的解析都不能替代法务审查；依赖更新仍必须经过测试和代码审查，固定提交、版本范围与自动更新不能替代来源审查、制品签名或生产环境保护。
- API 已为每次请求生成 `X-Request-Id`，请求完成日志与安全审计共同记录该请求 ID 和当前 release revision，支持跨事件、跨版本定位故障；完成日志只包含方法、稳定路由模板、状态、结果和延迟。动态计划、记录和设备标识会替换为参数名，未匹配路径统一为低基数标签，查询参数、正文、Cookie、用户标识和学习内容不会写入该日志。内部 API、遥测 sink 或共享限流后台清理失败时也只输出请求 ID、release、低基数路径和稳定错误类型，不打印可能包含凭据、学习内容或依赖地址的原始异常。客户端提前断开时以隐私安全的 `499` 和 `client-disconnected` 终止原因结算请求日志、安全审计与容量指标，避免中断的 Agent 请求从观测数据中消失或永久占用进行中计数。安全审计同样不写入原始账号或设备 ID，仅保留稳定截断哈希引用供短期事件关联；这些引用仍须受 14 天保留和运维访问控制约束。`/api/health` 会在启用同步时执行有界连接等待的 PostgreSQL 就绪检查，依赖失败则返回不含连接信息的 `503`，使部署健康检查不会接纳数据库不可用的 release。同一实例同时发生的就绪检查共享一个在途查询，但不缓存结果；下一批探针仍会重新验证依赖，兼顾数据库资源保护和故障发现时效。健康响应同时公开连接池上限、打开、空闲、使用中、等待数量和饱和状态，不包含账号、查询文本、地址或连接信息，可用于容量告警。生产仍需接入集中采集、保留策略、SLO 看板和告警。
- API 与 dev Web 入口已统一禁止跨站嵌入、MIME 嗅探、Referrer 泄露和未使用的摄像头、麦克风、定位、支付与 USB 权限；Web CSP 只允许同源脚本、样式、网络连接和静态资源，API CSP 不允许把 JSON 当作可执行页面加载。页面使用系统字体，不再向第三方字体服务发送访问请求。正式公网入口仍需在 TLS 终止层配置并验证 HSTS。
- API 对畸形 JSON 只返回稳定语法错误，不暴露运行时可能截取的学习内容；OIDC 回调拒绝原因也不回显身份提供商或攻击者控制的查询参数。结构化字段校验仍保留可操作的固定错误，便于客户端纠正请求。
- dev 部署在安装依赖前会把选定 Node 二进制置于 PATH 首位并输出实际 Node/npm 版本；健康门会核对 API 与 Web 进程的 `/proc` 二进制路径，并要求响应中的 `releaseRevision` 与待部署提交完全一致，避免旧进程以健康响应误通过发布门。`DEPLOYED_COMMIT` 缺失时本地源码运行报告 `null`，部署文件格式异常则 API 拒绝启动。成功 release 会原子更新远程部署与备份运行器；publisher 在 revision 已部署时仍调用远端轻量对账，仅在内容或执行权限漂移时修复运行器，覆盖应用激活后、运行器刷新前进程中断的恢复窗口。systemd 用户 unit 仍是 dev 主机控制面配置；`control-plane.sh status` 会检查 repo/主机 unit 漂移、启用与运行状态及实际 Node 路径，`install` 会串行备份、原子安装并在 reload/restart 后验证，失败则恢复备份。API 与 Web unit 强制只读文件系统视图、私有临时目录、禁止提权及内核参数/控制组接口保护等 Node 兼容沙箱基线；新增写路径或地址族必须按最小权限显式评审。当前 dev 用户管理器不能更改 capability bounding set，因此设备、内核模块、内核日志和时钟隔离留待生产服务管理器重新评估。
- 单账号默认最多保留 100 个同时具有有效会话的设备，可用 `AUTH_MAX_ACTIVE_DEVICES` 收紧。登录回调会先锁定账号、清理已无有效会话的设备，再原子检查上限；超限时以可重试 `429` 拒绝，避免重复或并发 OIDC 回调无界放大设备与会话记录。达到上限的学习者可从任一仍登录设备撤销旧设备，或等待会话过期后重新登录。
- 所有读取正文的 Agent 与同步端点只接受 `application/json`，使浏览器跨站提交必须先通过 CORS 预检；五类 Agent 请求限制为 64 KiB，避免异常学习内容放大模型输入 token 和内存成本，同步正文则保留 1 MB 上限。两种边界都会在解析前拒绝超限的声明长度，并对分块传输继续执行流式上限。精确来源校验仍是认证写操作和启用账号预算的模型调用的独立保护层。
- 64 KiB 正文边界内还会对五类 Agent 的学习目标、当前任务、学习者上下文、成果、复习薄弱点和主动回忆答案实施独立字段或条目上限，并对每层对象执行精确字段白名单；缺失数值、非法任务类型、未知嵌套字段和超限数组都会在模型调用前拒绝。浏览器对目标、成果和回忆答案复用同一上限，减少学习者在服务端拒绝后丢失输入的风险。
- 浏览器同步、认证与 Agent 响应以及服务端模型、OIDC discovery、令牌和 JWKS 响应都在字节上限内严格按 UTF-8 解码；畸形编码会被拒绝而不是替换字符后继续处理，避免学习证据、身份元数据或结构化模型输出被静默改写。模型编码失败以稳定网关错误结束且不自动重试。
- API 传输层将请求头等待限制为 15 秒、请求正文接收限制为 30 秒、空闲 keep-alive 限制为 5 秒，并限制每个请求的头数量和单连接请求数；这些接收期限不限制正文接收完毕后的 Agent 模型响应时间。进程终止会拒绝新连接、立即回收空闲连接，并用同一个 10 秒总截止时间覆盖在途请求排空和数据库等依赖清理；任一阶段超时都会强制关闭残留连接并以失败状态只退出一次，避免部署或回滚被卡住。
- 每个 API 实例默认最多同时执行 20 个 Agent 请求，可通过 `AI_MAX_CONCURRENT_AGENT_REQUESTS` 按实例资源和模型连接预算调整，启动配置硬上限为 100；过载请求在读取学习正文和调用模型前以可重试 `503` 拒绝。健康端点只暴露上限、进行中数量和累计拒绝数。多实例生产环境仍需在入口层和厂商侧配置全局并发或排队保护，单实例边界不能替代集群容量规划。
- API 的 PostgreSQL 连接池默认限制为每实例 10 条连接，并限制连接获取、空闲连接、连接生命周期、服务端语句、客户端查询等待和空闲事务时间；所有边界可通过 `DATABASE_*` 环境变量按托管数据库连接预算调整，但启动时分别限制为最多 100 条连接、60 秒连接获取、10 分钟空闲、120 秒语句、180 秒查询等待、120 秒空闲事务和 24 小时连接生命周期，且客户端查询时限必须晚于服务端语句取消，以优先回收数据库工作。单账号活跃设备配置最多为 1,000，避免错误运维值移除状态容量保护。非回环数据库必须显式设置 `DATABASE_TLS_MODE=verify-full`，客户端会验证服务器证书和主机名；连接 URL 中的 TLS 参数会被拒绝，避免弱模式或配置覆盖。生产容量规划必须把应用副本数乘以每实例连接上限，并为迁移、运维和故障切换预留连接。
- 高基数启动配置采用显式硬边界：允许来源最多 32 项且总计 16,384 字符，可信代理最多 64 项且总计 4,096 字符，套餐预算最多 32 项且 JSON 最多 32,768 字符；单个来源或 OIDC URL 最多 2,048 字符，Cookie 名称、OIDC 客户端 ID 和事务密钥分别最多 128、256 和 4,096 字符。服务在构造 URL、解析 JSON 或建立依赖前拒绝超限配置，避免误配置放大启动内存、逐请求来源匹配或套餐查找成本。
- 模型提供商 JSON 响应按流读取且最多接收 1 MB；OIDC discovery 与令牌响应分别限制为 64 KiB 和 256 KiB。模型调用除 30 秒单次尝试超时外，还具有跨重试、响应读取和退避等待的 60 秒默认总时限；`OPENAI_TOTAL_TIMEOUT_MS` 可在 120 秒硬上限内显式调整。结构化输出默认最多 4096 token，启动配置不得超过 32,768 token，避免错误运维值重新引入无界占用或单次异常成本。五类 Agent 的 JSON Schema 还分别限制文本长度和嵌套条目数，领域层会再次验证同一边界，并检查 Planner 阶段/任务标识唯一性；忽略 Schema 的兼容 Provider 因此不能把异常大但仍小于 1 MB 的对象写入学习状态。即使上游忽略输出 token 契约、使用分块传输、持续超时或返回异常元数据，API 也会取消或拒绝剩余响应，避免单请求无界占用进程内存、持久化空间与 Agent 并发名额。上游错误正文不会透传到浏览器；厂商请求 ID 只有符合最多 200 个受限 ASCII 字符的关联格式时才会进入响应和用量账本，避免兼容服务反射学习内容、凭据或高基数值。
- OIDC discovery、授权码交换和 JWKS 密钥获取默认各使用 10 秒请求时限，并由同一 `OIDC_UPSTREAM_TIMEOUT_MS` 启动配置在 60 秒硬上限内调整；JWKS 与令牌响应各限制为 256 KiB，discovery 限制为 64 KiB，且 JWKS 通过同一受控 HTTP 客户端获取。身份上游停滞或异常响应不会无限占用登录、回调连接或进程内存。生产值应低于入口请求时限，并结合身份提供商正常延迟验证。
- 浏览器对五类 Agent JSON 响应实施 1 MiB 流式上限，对认证 JSON 响应实施 64 KiB 上限，并以 9 MiB 上限覆盖同步分页和写入结果；超限的声明长度会在读取前拒绝，分块传输越界时会取消响应流。同步客户端还会在使用云端实体前验证实体类型、有界标识符、正安全整数 revision、时间戳和值字段，写入结果必须匹配请求实体，续页游标最多 256 字符；畸形响应不会进入本地同步元数据或条件写入。该边界限制异常服务端或受损代理占用单标签页内存及污染本地状态，但不能替代入口和服务端响应边界。
- 限流默认只使用与应用直连的网络地址。反向代理部署可通过 `TRUSTED_PROXY_ADDRESSES` 精确列出受信代理 IP；应用只在直连来源命中该清单时采用最右侧有效 `X-Forwarded-For` 地址，配置或请求异常则回退到直连地址，避免所有用户共享代理配额或客户端伪造限流身份。生产入口必须覆盖而不是原样透传客户端提供的转发头，并按实际代理拓扑验证地址选择。
- 未配置数据库时使用的单实例内存限流器最多保留 10,000 个客户端与路由范围组合；容量满时先回收过期窗口，对仍无法容纳的新身份安全拒绝，避免高基数来源让进程状态无界增长。生产多实例仍使用 PostgreSQL 原子共享限流，不能依赖该进程内边界替代入口层容量保护。
- 数据库迁移采用 expand/contract；上线前验证旧应用可在新 schema 上运行。独立迁移命令与 API 复用同一 PostgreSQL URL、证书和主机名验证及有界等待配置；非回环数据库未显式设置 `DATABASE_TLS_MODE=verify-full` 时在执行任何 schema 查询前拒绝启动，且迁移始终只使用一条连接。
- 数据库迁移运行器使用 PostgreSQL advisory lock 保证同一数据库同时只有一个执行者，并在 `schema_migrations` 保存每份 SQL 的 SHA-256。旧记录会在首次受保护运行时回填当前校验和；此后历史 SQL 与已记录内容不一致会在新迁移执行前失败。迁移文件一旦应用只能新增后续迁移，不能原地修改。
- 同步游标和幂等结果只保留 30 天；服务实例每天至多执行一次索引支持的过期清理。过期游标返回稳定错误，客户端可不带游标执行完整同步；学习计划和每日记录不受该清理影响。
- 过期认证会话和已经没有保留会话的废弃设备只保留 30 天；登录或令牌轮换会每天至多触发一次索引支持的会话清理，并在账号事务内收敛该账号的废弃设备。每日会话清理失败不会阻断认证，并会输出不含账号、设备或数据库内容的错误类型；仍有未过期会话的设备不会被删除。
- 同步用户、设备、实体、幂等操作和游标标识符统一限制为 1–256 个字符，并在数据库查询前验证，避免异常客户端用超长索引键放大存储与查询成本。
- 账号同步快照按变更序列每页最多返回 250 个当前实体，并把实体编码总量限制为 8 MiB；达到任一边界都会生成账号隔离的不透明游标继续读取，避免长期多目标账号产生无界 HTTP 响应。浏览器流式读取并在 9 MiB 处取消异常分页，同时把一次完整同步限制为 25,000 个不同实体和 100 页。服务端再将单账号长期保留限制为 25,000 个实体和 256 MiB 编码 JSON；事务内账号计数器使多实例并发写入不能越过边界，超额写入返回不可重试的 `507` 且不改变已有数据。生产仍需建立配额接近率告警、用户归档/删除策略，并在真实容量环境验证大实体页延迟、数据库客户端内存和并发写入压力。
- dev PostgreSQL 备份在发布前会拒绝空输出并通过 `pg_restore --list` 验证 custom archive 可读取；最终名称带随机后缀，避免同秒运行互相覆盖，且生成权限为 `0600` 的 SHA-256 sidecar 供恢复前检查静态损坏。超过 7 天的归档与 sidecar 成对清理，失败则只清理未发布临时文件。这些检查只能证明创建时结构可解析并发现后续字节变化，仍不能替代隔离恢复演练、异地副本或明确 RPO/RTO。
- 建立异地加密备份、恢复点目标（RPO）、恢复时间目标（RTO）和定期恢复演练。
- 定义可用性与延迟 SLO，集中采集指标、结构化日志、追踪和告警，并明确值班负责人。
- 执行容量、故障注入和降级测试；模型或同步服务不可用时保持数据安全和可解释状态。

### AI、成本与产品安全

- 当前可按认证账号和 Agent 功能记录模型输入/输出 token、模型与估算微美元成本，并通过显式配置的月度 token 与金额上限在模型调用前熔断。启用账号预算的模型入口同时要求精确来源匹配，跨站请求会在预算查询、正文读取和模型调用前拒绝。可选的 `AI_SUBSCRIPTION_ENTITLEMENTS_REQUIRED=true` 会再从 PostgreSQL 读取服务端权益，并要求 `AI_PLAN_BUDGETS_JSON` 将每个允许的套餐映射到独立的月度 token 与金额硬配额；套餐切换在下一次请求生效，未配置套餐安全拒绝。账本和权益记录都不保存学习正文，并随账号删除级联清除。
- 当前已对五类 Agent 入口实施多实例共享的分钟级客户端配额，并在健康端点按功能暴露隐私安全的容量、失败和限流指标。实时模型启动时默认要求账号用量账本，因此同时要求认证会话和完整预算配置，避免模型凭据误配置成公开未认证、未计量的 Agent API；显式 `AI_ALLOW_UNMETERED_LIVE_MODEL=true` 只保留给隔离的本地烟雾测试，部署环境不得使用。账号预算优先统计厂商返回的成功调用用量；compatible Provider 缺少用量时按完整请求与结构化输出 UTF-8 字节数保守记账，其他未实现等价估算的实时 Provider 在认证预算上下文安全失败，避免静默绕过成本熔断。预算按已入账金额在下一次请求前判断；可选应用级全局月度金额上限会汇总所有账号并统一熔断。提供商返回请求 ID 时，账本只记录同一响应一次，防止记账步骤重放造成预算重复扣减；不返回请求 ID 的 compatible Provider 仍逐次记账。每次模型响应默认限制为 4096 个输出 token，且配置硬上限为 32,768，缩小单次和在途调用的输出成本风险；并发检查窗口、估算误差和输入成本仍可能造成有限超额。携带 Bearer API 密钥的模型请求拒绝 HTTP 重定向，避免兼容端点或代理把凭据和学习内容转发到非预期主机；端点迁移必须显式更新配置并重新验证。
- 生产仍需由支付供应商 webhook 维护服务端权益，并增加厂商侧独立硬金额上限、集中告警、失败调用成本对账和单位经济分析。应用级全局熔断不能替代厂商侧保护。
- 已建立覆盖五类 Agent 的九案例最小评估集，复用生产领域校验并对内嵌评分指令、单案例延迟、单案例输出 token 和整组 token 实施发布门槛；发布前按 `docs/agent-evaluation.md` 比较 Prompt 与模型版本。公开发布仍需扩展高风险领域、偏见和越权指导评估。
- 对模型输出保留结构化校验、内容边界和清晰的非权威提示；高风险学习领域需要额外政策。
- 明确免费、付费和团队版本的配额、数据边界、支持承诺与退款规则。

### 商业运营

- 建立支付、订阅状态、发票、税务和退款流程，并让权限以服务端订阅状态为准。
- 增加产品分析的最小事件集，同时遵守数据最小化和可撤回同意。
- 准备客服、事故沟通、滥用处理、漏洞响应和第三方供应商故障预案。

## 发布阶段

1. **内部 dev**：持续自动部署，验证功能、迁移、备份与恢复。
2. **受控 alpha**：少量真实用户，托管身份、集中监控、明确数据政策，不承诺正式 SLO。
3. **付费 beta**：完成计费、支持、成本上限、安全审查与灾难恢复演练。
4. **正式生产**：通过全部上线门槛，启用变更审批、事故响应和值班制度。

任何阶段升级都必须由证据驱动；功能数量不能替代安全、可靠性、合规和商业运营能力。
