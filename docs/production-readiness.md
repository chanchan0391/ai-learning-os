# 生产与商业化就绪基线

## 当前结论

当前系统具备可运行的 dev 全栈基线，包括实时模型、PostgreSQL 同步、OIDC、会话、限流、备份和自动部署，但尚不满足公开生产发布条件。dev 自动部署依赖个人开发机连接内网服务器，只用于持续验收，不能视为生产交付架构。

## 上线门槛

### 身份与数据安全

- 使用托管身份提供商替换 Dex 静态测试账号，完成注册、找回、MFA 与异常登录策略。
- 对所有用户数据验证服务端租户隔离，并增加越权与批量访问测试。
- 使用云端密钥管理和短期身份，不在主机文件、CI 变量或日志中保存长期模型与部署凭据。
- 完成隐私政策、服务条款、数据处理方清单、用户同意、数据导出与删除时限。

### 可靠性与运维

- 建立独立 CI/CD Runner、受保护生产环境、不可变制品、审批、健康检查与一键回滚。
- API 已为每次请求生成 `X-Request-Id`，并输出仅含请求 ID、方法、稳定路由模板、状态、结果和延迟的 JSON 行完成日志；动态计划、记录和设备标识会替换为参数名，未匹配路径统一为低基数标签，查询参数、正文、Cookie、用户标识和学习内容不会写入该日志。客户端提前断开时以隐私安全的 `499` 和 `client-disconnected` 终止原因结算请求日志、安全审计与容量指标，避免中断的 Agent 请求从观测数据中消失或永久占用进行中计数。安全审计同样不写入原始账号或设备 ID，仅保留稳定截断哈希引用供短期事件关联；这些引用仍须受 14 天保留和运维访问控制约束。`/api/health` 会在启用同步时执行有界连接等待的 PostgreSQL 就绪检查，依赖失败则返回不含连接信息的 `503`，使部署健康检查不会接纳数据库不可用的 release。同一实例同时发生的就绪检查共享一个在途查询，但不缓存结果；下一批探针仍会重新验证依赖，兼顾数据库资源保护和故障发现时效。健康响应同时公开连接池上限、打开、空闲、使用中、等待数量和饱和状态，不包含账号、查询文本、地址或连接信息，可用于容量告警。生产仍需接入集中采集、保留策略、SLO 看板和告警。
- API 与 dev Web 入口已统一禁止跨站嵌入、MIME 嗅探、Referrer 泄露和未使用的摄像头、麦克风、定位、支付与 USB 权限；Web CSP 只允许同源脚本、样式、网络连接和静态资源，API CSP 不允许把 JSON 当作可执行页面加载。页面使用系统字体，不再向第三方字体服务发送访问请求。正式公网入口仍需在 TLS 终止层配置并验证 HSTS。
- 单账号默认最多保留 100 个同时具有有效会话的设备，可用 `AUTH_MAX_ACTIVE_DEVICES` 收紧。登录回调会先锁定账号、清理已无有效会话的设备，再原子检查上限；超限时以可重试 `429` 拒绝，避免重复或并发 OIDC 回调无界放大设备与会话记录。达到上限的学习者可从任一仍登录设备撤销旧设备，或等待会话过期后重新登录。
- 所有读取正文的 Agent 与同步端点只接受 `application/json`，使浏览器跨站提交必须先通过 CORS 预检；五类 Agent 请求限制为 64 KiB，避免异常学习内容放大模型输入 token 和内存成本，同步正文则保留 1 MB 上限。两种边界都会在解析前拒绝超限的声明长度，并对分块传输继续执行流式上限。精确来源校验仍是认证写操作和启用账号预算的模型调用的独立保护层。
- API 传输层将请求头等待限制为 15 秒、请求正文接收限制为 30 秒、空闲 keep-alive 限制为 5 秒，并限制每个请求的头数量和单连接请求数；这些接收期限不限制正文接收完毕后的 Agent 模型响应时间。进程终止会拒绝新连接、立即回收空闲连接，并用同一个 10 秒总截止时间覆盖在途请求排空和数据库等依赖清理；任一阶段超时都会强制关闭残留连接并以失败状态只退出一次，避免部署或回滚被卡住。
- 每个 API 实例默认最多同时执行 20 个 Agent 请求，可通过 `AI_MAX_CONCURRENT_AGENT_REQUESTS` 按实例资源和模型连接预算调整；过载请求在读取学习正文和调用模型前以可重试 `503` 拒绝。健康端点只暴露上限、进行中数量和累计拒绝数。多实例生产环境仍需在入口层和厂商侧配置全局并发或排队保护，单实例边界不能替代集群容量规划。
- API 的 PostgreSQL 连接池默认限制为每实例 10 条连接，并限制连接获取、空闲连接、连接生命周期、服务端语句、客户端查询等待和空闲事务时间；所有边界可通过 `DATABASE_*` 环境变量按托管数据库连接预算调整，且客户端查询时限必须晚于服务端语句取消，以优先回收数据库工作。生产容量规划必须把应用副本数乘以每实例连接上限，并为迁移、运维和故障切换预留连接。
- 模型提供商 JSON 响应按流读取且最多接收 1 MB；OIDC discovery 与令牌响应分别限制为 64 KiB 和 256 KiB。模型调用除 30 秒单次尝试超时外，还具有跨重试、响应读取和退避等待的 60 秒默认总时限，可通过 `OPENAI_TOTAL_TIMEOUT_MS` 显式收紧或放宽。即使上游忽略输出 token 契约、使用分块传输、持续超时或返回异常元数据，API 也会取消剩余响应，避免单请求无界占用进程内存与 Agent 并发名额。
- OIDC discovery、授权码交换和 JWKS 密钥获取默认各使用 10 秒请求时限，并由同一 `OIDC_UPSTREAM_TIMEOUT_MS` 启动配置在 60 秒硬上限内调整；JWKS 与令牌响应各限制为 256 KiB，discovery 限制为 64 KiB，且 JWKS 通过同一受控 HTTP 客户端获取。身份上游停滞或异常响应不会无限占用登录、回调连接或进程内存。生产值应低于入口请求时限，并结合身份提供商正常延迟验证。
- 浏览器对五类 Agent JSON 响应实施 1 MiB 流式上限，对认证 JSON 响应实施 64 KiB 上限，并以 9 MiB 上限覆盖同步分页和写入结果；超限的声明长度会在读取前拒绝，分块传输越界时会取消响应流。该边界限制异常服务端或受损代理占用单标签页内存，但不能替代入口和服务端响应边界。
- 限流默认只使用与应用直连的网络地址。反向代理部署可通过 `TRUSTED_PROXY_ADDRESSES` 精确列出受信代理 IP；应用只在直连来源命中该清单时采用最右侧有效 `X-Forwarded-For` 地址，配置或请求异常则回退到直连地址，避免所有用户共享代理配额或客户端伪造限流身份。生产入口必须覆盖而不是原样透传客户端提供的转发头，并按实际代理拓扑验证地址选择。
- 未配置数据库时使用的单实例内存限流器最多保留 10,000 个客户端与路由范围组合；容量满时先回收过期窗口，对仍无法容纳的新身份安全拒绝，避免高基数来源让进程状态无界增长。生产多实例仍使用 PostgreSQL 原子共享限流，不能依赖该进程内边界替代入口层容量保护。
- 数据库迁移采用 expand/contract；上线前验证旧应用可在新 schema 上运行。
- 数据库迁移运行器使用 PostgreSQL advisory lock 保证同一数据库同时只有一个执行者，并在 `schema_migrations` 保存每份 SQL 的 SHA-256。旧记录会在首次受保护运行时回填当前校验和；此后历史 SQL 与已记录内容不一致会在新迁移执行前失败。迁移文件一旦应用只能新增后续迁移，不能原地修改。
- 同步游标和幂等结果只保留 30 天；服务实例每天至多执行一次索引支持的过期清理。过期游标返回稳定错误，客户端可不带游标执行完整同步；学习计划和每日记录不受该清理影响。
- 过期认证会话和已经没有保留会话的废弃设备只保留 30 天；登录或令牌轮换会每天至多触发一次索引支持的会话清理，并在账号事务内收敛该账号的废弃设备。每日会话清理失败不会阻断认证，并会输出不含账号、设备或数据库内容的错误类型；仍有未过期会话的设备不会被删除。
- 同步用户、设备、实体、幂等操作和游标标识符统一限制为 1–256 个字符，并在数据库查询前验证，避免异常客户端用超长索引键放大存储与查询成本。
- 账号同步快照按变更序列每页最多返回 250 个当前实体，并把实体编码总量限制为 8 MiB；达到任一边界都会生成账号隔离的不透明游标继续读取，避免长期多目标账号产生无界 HTTP 响应。浏览器流式读取并在 9 MiB 处取消异常分页，同时把一次完整同步限制为 25,000 个不同实体和 100 页，避免错误服务端或持续写入造成无界请求与内存增长。当前 PostgreSQL 查询仍会先取最多 251 行再执行编码字节裁剪，因此达到账号上限前仍需建立容量告警、归档或分区策略，并在真实容量环境验证大实体页延迟、数据库客户端内存和并发写入压力。
- 建立异地加密备份、恢复点目标（RPO）、恢复时间目标（RTO）和定期恢复演练。
- 定义可用性与延迟 SLO，集中采集指标、结构化日志、追踪和告警，并明确值班负责人。
- 执行容量、故障注入和降级测试；模型或同步服务不可用时保持数据安全和可解释状态。

### AI、成本与产品安全

- 当前可按认证账号和 Agent 功能记录模型输入/输出 token、模型与估算微美元成本，并通过显式配置的月度 token 与金额上限在模型调用前熔断。启用账号预算的模型入口同时要求精确来源匹配，跨站请求会在预算查询、正文读取和模型调用前拒绝。可选的 `AI_SUBSCRIPTION_ENTITLEMENTS_REQUIRED=true` 会再从 PostgreSQL 读取服务端权益，并要求 `AI_PLAN_BUDGETS_JSON` 将每个允许的套餐映射到独立的月度 token 与金额硬配额；套餐切换在下一次请求生效，未配置套餐安全拒绝。账本和权益记录都不保存学习正文，并随账号删除级联清除。
- 当前已对五类 Agent 入口实施多实例共享的分钟级客户端配额，并在健康端点按功能暴露隐私安全的容量、失败和限流指标。账号预算只统计厂商返回的成功调用用量，并按已入账金额在下一次请求前判断；可选应用级全局月度金额上限会汇总所有账号并统一熔断。提供商返回请求 ID 时，账本只记录同一响应一次，防止记账步骤重放造成预算重复扣减；不返回请求 ID 的 compatible Provider 仍逐次记账。每次模型响应默认限制为 4096 个输出 token，缩小单次和在途调用的输出成本风险；并发检查窗口和输入成本仍可能造成有限超额。携带 Bearer API 密钥的模型请求拒绝 HTTP 重定向，避免兼容端点或代理把凭据和学习内容转发到非预期主机；端点迁移必须显式更新配置并重新验证。
- 生产仍需由支付供应商 webhook 维护服务端权益，并增加厂商侧独立硬金额上限、集中告警、失败调用成本对账和单位经济分析。应用级全局熔断不能替代厂商侧保护。
- 已建立覆盖五类 Agent 的九案例最小评估集，复用生产领域校验并对内嵌评分指令、单案例延迟、单案例输出 token 和整组 token 实施发布门槛；发布前按 `docs/agent-evaluation.md` 比较 Prompt 与模型版本。公开发布仍需扩展高风险领域、偏见和越权指导评估。
- 对模型输出保留结构化校验、内容边界和清晰的非权威提示；高风险学习领域需要额外政策。
- 明确免费、付费和团队版本的配额、数据边界、支持承诺与退款规则。

### 商业运营

- 建立支付、订阅状态、发票、税务和退款流程，并让权限以服务端订阅状态为准。
- 增加产品分析的最小事件集，同时遵守数据最小化和可撤回同意。
- 准备客服、事故沟通、滥用处理、漏洞响应和第三方供应商故障预案。

## 发布阶段

1. **内部 dev**：持续自动部署，验证功能、迁移、备份与恢复。
2. **受控 alpha**：少量真实用户，托管身份、集中监控、明确数据政策，不承诺正式 SLO。
3. **付费 beta**：完成计费、支持、成本上限、安全审查与灾难恢复演练。
4. **正式生产**：通过全部上线门槛，启用变更审批、事故响应和值班制度。

任何阶段升级都必须由证据驱动；功能数量不能替代安全、可靠性、合规和商业运营能力。
