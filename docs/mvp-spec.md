# AI Learning OS MVP 产品说明

## 目标

验证一个核心假设：把模糊学习目标立即转化为可完成的路线和当天行动，能否降低开始学习的阻力，并帮助用户形成完整的“学习—实践—反馈—复盘”闭环。

## 首个垂直切片

### 用户输入

- 学习主题
- 当前能力
- 目标结果
- 每日可投入时间
- 学习周期

### 系统输出

- 覆盖整个周期的四阶段路线
- 每天的诊断、学习、实践和复盘任务
- 每项任务的时间预算
- 可持续保存的完成状态

### 成功标准

1. 用户可以在两分钟内建立第一个计划。
2. 当天任务总时长严格等于用户可投入时间。
3. 每天同时包含输入、输出和反思，而不只是阅读材料。
4. 用户刷新页面后不会丢失计划、每日反馈和历史进度。
5. 用户完成当天闭环后，可以基于难度反馈进入下一天。

## 产品决策

### 确定性规划器作为开发基线

没有模型凭据时使用确定性规则，提供稳定的测试基线并支持完整产品开发。配置模型后，Planner Agent 通过服务端 `ModelProvider` 生成相同的 `LearningPlan` 输出，界面和领域模型不需要改变。

### 首个目标用户

默认示例采用“有 Java 背景、希望成为 AI Agent 工程师”的技术人员，与项目冷启动策略一致。规划器也支持其他学习主题的通用路线。

### 数据边界

学习计划、每日任务、教学回答、成果提交、评估结果、难度反馈和历史进度首先保存在浏览器本地。当前持久化格式为版本 3；版本 1 计划和版本 2 学习记录会自动迁移，无法验证的数据会安全重置。用户可以随时下载带格式版本与导出时间的 JSON 副本，也可以导入经完整校验的副本；恢复前会预览目标和学习日并要求确认替换。用户还可以通过二次确认永久删除当前浏览器中的全部学习数据。登录并配置同步服务后，本地更改会进入持久自动队列：快速编辑被合并，离线更改在恢复连接后重试，冲突必须明确选择版本。创建目标、教学会话或成果评估时，浏览器会把当前步骤所需内容发送到本机 API；启用实时模型后，本机 API 会把这些内容发送到配置的模型厂商。界面已提供简短提示，正式上线前仍必须增加完整的隐私告知和数据保留策略。

## 暂不包含

- 托管式账号注册和生产级云同步服务
- 可按日期回看的完整日历视图
- 可根据复习表现动态调整间隔的完整 Review Agent（当前已用固定的第 1、3、7 天间隔形成最小闭环）
- 课程市场、社区和企业管理后台

Teacher 与 Evaluator 已接入当前学习任务：学习任务要求完成主动理解检查，实践任务要求提交成果并展示四维反馈。当前是单轮、结构化教学流程，不是开放式多轮对话。

Review Agent 的首个垂直切片不增加新的持久化副本，而是从已保存的 Evaluator 结果派生复习安排。`needs-support`、`developing` 或仍含误解的结果会在原学习日后的第 1、3、7 天进入诊断任务，要求用户先主动纠错和复述最小下一步，再继续当天内容。

## 后续验证指标

- 目标创建完成率
- 第一天任务开始率和完成率
- 连续 7 天学习率
- 用户对任务难度和相关性的评分
- 计划被人工修改的比例
