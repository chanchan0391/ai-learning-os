# dev 环境恢复演练

## 目标

验证开发部署的 PostgreSQL 备份可以恢复，并确认恢复后的结构与关键数据可读；同时验证真实 Dex OIDC discovery 和应用登录发起边界。演练不覆盖生产异地备份，也不把测试账号、Cookie、数据库连接串或其他凭据写入仓库。

## 2026-08-01 演练记录

- 环境：通过 SSH 隧道访问、只绑定远端回环地址的 `dev` 环境。
- 备份：UTC 2026-08-01 生成的 PostgreSQL custom-format 每日备份，大小 23,219 字节。
- 恢复：创建隔离的临时数据库，以 `pg_restore --exit-on-error --no-owner --no-privileges` 完整恢复，验证后立即删除临时数据库。
- 结构验证：恢复出 10 个 `public` 表，`schema_migrations` 包含 4 条迁移记录。
- 数据验证：恢复库中的 `users` 表包含预期的 1 条开发账号记录；未输出账号内容或其他个人数据。
- OIDC 验证：Dex discovery 返回与配置完全一致的 issuer，授权、token 和 JWKS 端点均保持同一回环来源；`/api/auth/login` 返回 `302`、OIDC 事务 Cookie，并跳转至 Dex 授权端点。
- 服务验证：`/api/health` 返回 `200`，实时模型与同步存储均启用；Web、API、Dex 和 PostgreSQL 服务均在运行。
- 结果：备份可用于同版本数据库恢复，OIDC 登录发起链路可用。真实浏览器完成授权回调、创建服务端会话并执行跨设备同步仍需单独验收。

## 下次演练

1. 选择最新备份并记录生成时间、文件大小与校验和，不记录文件内容。
2. 使用全新的隔离数据库恢复，禁止覆盖运行中的应用数据库。
3. 验证迁移数量、核心表存在性和非敏感行数，再运行只读同步仓库检查。
4. 通过真实浏览器完成 OIDC 回调，验证会话轮换、一次上传和一次云端恢复。
5. 删除临时恢复库并确认运行中服务的健康状态未受影响。
