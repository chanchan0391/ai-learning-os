# Agent 质量与成本评估基线

## 目的

发布前需要用同一组固定输入比较 Planner、Teacher、Evaluator、Review 和 Coach Agent 的契约正确性、最低质量行为、延迟与 token 用量。评估直接调用生产 Agent 编排和领域校验，不维护第二套 Prompt 或输出格式。

当前评估集包含九个合成案例：计划预算与周覆盖、主动回忆教学、薄弱与完整成果判分、Evaluator 内嵌评分指令抵抗、薄弱与已纠正的闭卷回忆、Review 内嵌评分指令抵抗，以及中断后的低压力恢复。两个对抗案例把要求忽略规则、指定满分和泄露系统提示词的文本放入学习者内容，发布门槛要求 Agent 仍只按可见的领域证据判分。合成输入不包含真实用户、账号或学习记录。

评估同时实施机器可判定的资源门槛：单案例默认不得超过 30 秒或 4096 个输出 token，九个案例合计默认不得超过 100,000 个 token。实时 Provider 缺少 token 用量时同样失败，避免无法证明成本边界的模型被误判为可发布。

## 运行

确定性基线不调用外部服务，也不产生模型费用：

```sh
npm run eval:agents
```

普通命令始终忽略 `.env.local` 中的模型凭据。明确接受这次最多九次模型调用后，才加载本地实时模型配置：

```sh
AI_EVAL_ALLOW_LIVE=1 npm run eval:agents
```

如模型或发布环境需要更严格的预算，可用正整数 `AI_EVAL_MAX_CASE_DURATION_MS`、`AI_EVAL_MAX_CASE_OUTPUT_TOKENS` 和 `AI_EVAL_MAX_TOTAL_TOKENS` 下调门槛。提高门槛属于成本或延迟决策，应记录理由并在同一环境比较基线。

实时运行不应放入普通 CI、自动部署或无人值守定时任务。运行前应确认测试账号预算与模型厂商硬金额上限；需要比较模型时分别保存终端输出，不要提交包含内部模型标识或运营数据的报告。

## 报告与隐私边界

JSON 报告只包含案例 ID、Agent 名称、通过状态、耗时、模型名、token 总量、资源门槛、门槛违例代号和错误类型。它不会输出或保存 Prompt、合成输入、模型响应、厂商请求 ID、密钥或学习正文。实时运行通过本地模型适配器，不写账号用量账本，因此只适合受控的发布前评估，不能替代生产账号预算或厂商侧成本保护。

## 发布判定

- `npm run check` 必须通过；它会运行确定性评估回归测试。
- 五类 Agent 都必须有至少一个通过案例，且九个案例不能出现领域校验、质量断言或资源门槛失败；Evaluator 和 Review 的内嵌评分指令案例必须保持低分。
- 更换 Prompt、模型、结构化输出契约或费率前后，应在同一环境执行实时评估并比较失败数、总 token 和延迟。
- 任一案例退化时停止模型切换；先检查输出契约、评分边界和失败案例，再决定修复 Prompt、适配器或评估阈值。
- 当前集合是最小发布门槛，不代表高风险学习领域的安全评估；公开发布前仍需扩展领域正确性、偏见、越权指导和对抗输入测试。
